# ABC 投放日报自动分级 MVP

## 可复用现有内容

- `withdraw.py` 提供现有 PostgreSQL 日报查询结果，可作为默认数据源；不修改其 SQL 或覆盖数据库表。
- CSV/XLSX 数据源支持现有 SQL 报表字段（包括“昨日”“前7日明细”“前7日均值”）和原始英文核心字段。
- `ads_daily_report_1022.csv` 是可直接回测的 2026-10-22 日报数据；“渠道”列作为可用投放线 ID。没有投放线 ID 时，使用「组别+投手+媒体+系统」组合键并检查日期重复。
- `AuGradeCo.py` 保留为原入口，处理逻辑放入新模块。

原始 `ads_daily_merged.csv` 不含 A/B/C 组映射和完整日报粒度，不能单独可靠判组或生成投放线日报。请使用 SQL 日报查询结果，或先补充含“组别”的日报导出。项目中没有找到《投放日报_领导速览_分级结论同步更新》Excel 模板，因此当前输出使用新建的简洁工作簿样式，不修改源 CSV。

## 安装与运行

```powershell
python -m pip install -r requirements.txt
python AuGradeCo.py
```

不传 `--input` 时使用 `withdraw.query_local_database()`。也可以指定已有 CSV/XLSX：

```powershell
python AuGradeCo.py --input ads_daily_report_1022.csv
python AuGradeCo.py --input ads_daily_report_1022.csv --date 2026-10-22
python AuGradeCo.py --input ads_daily_report_1022.csv --date 2026-10-22 --benchmark-labels 结论_2026-10-22.xlsx
```

生成文件放入 `reports/`，包括日报工作簿、自动/人工差异 CSV、回测摘要 JSON 和 SQLite 历史库。传入 `--benchmark-labels` 后，还会生成基于人工标签粒度的历史回测差异 CSV 和分级指标。源数据文件不会被覆盖。

工作簿中的“人工复核记录”页允许填写“人工最终分级”“人工修正原因”“实际处理动作”“后续效果”。复核完成后可导入并保存：

```powershell
python AuGradeCo.py --input ads_daily_report_1022.csv --import-review reports/投放日报_分级结论_20261022.xlsx
```

导入时按日期和记录键更新历史库；同日重复运行时保留人工分级。新日期不会自动继承前一日人工结论。

## MVP 范围与规则

- 仅处理 A/B/C 组；代投、DSP、其他组别不进入领导速览。
- 原始日报中的“成本偏离阈值%”（含“超成本阀值”等别名）保留在领导速览、TOP清单及 A/B/C 趋势表中；领导速览表顶部按实际生效分级汇总各级渠道数。
- A/B/C 趋势表保留源数据中的“分级”和“结论”；昨日源字段为空时，以历史人工覆盖优先的实际生效分级及自动结论补齐。
- 有前7日明细时，先汇总分子分母再计算 CPA、ROAS、ARPPU、CPC 和漏斗率；明细日期不齐会降低基线可信度，不把缺失日当作零。
- 只有“前7日均值”时才回退使用该均值，并在质量提醒中注明较低可信度。
- 复充率仅对可用日比例取算术平均，不称为队列加权率；缺失复充率不会被当成0或直接判留存异常。
- 安装注册率超过100%只生成归因/时间窗口核验提醒，不单独判 P0。
- 人工最终分级优先于自动建议；自动处理不会改动广告预算。
- “高消耗”默认 $1,000，“严重恶化”及持续天数等在 `config.json` 集中配置。它们是待人工校准的初始规则，不代表已验证门槛。
- Google/App Store 次日复充标准及 PWA/H5 财务KPI未配置时不套用 FB/TK 或 Android/iOS 阈值，降低置信度并提示人工确认。

## 验证与当前历史资料限制

运行单元测试：

```powershell
python -m unittest discover -s tests -v
```

以 2026-10-22 样例执行后，`回测摘要`列出人工标签覆盖率；未提供人工分级时不输出虚构的一致率、准确率或召回率。`ads_daily_report_22.csv` 的“分级”列为空，但单独的 `结论_2026-10-22.xlsx` 提供了人工标签。本回测先将带渠道ID的详细数据按「组别+投手+媒体+系统」汇总到人工标签的粒度，再逐条比较；不会将汇总标签贴到单一渠道线。

本地回测（10/22、53条人工标签）总体一致率为 **45.3%**。样本内 P0 precision/recall 为 66.7%/66.7%，P1 为 81.8%/75.0%；P0 漏报 2 条、P1 漏报 3 条。没有人工 P2-A/P4 标签，因此这些级别的召回率不可计算。该回测仅供初始规则校准，不代表人工标签是绝对真值。

指定猴子｜B组｜FB iOS 案例已按组合键汇总验证：消耗 $2,812.53、CPA $40.179（前7日 $33.417）、ROAS 30.38%（前7日 30.74%）；CPA 上升约20.24%，归因可用，主要不利贡献来自点击安装率及安装注册率下降，CPC下降形成抵消。自动建议 P1，与人工标签一致。
